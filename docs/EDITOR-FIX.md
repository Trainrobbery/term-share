# 사전 입력기 수정 · alpha.3

## 보고된 현상

1. 사전 입력기에 쓴 글이 보이지 않음.
2. 한글 `가`가 `가ㄱ`처럼 중복되어 입력됨.

## 코드에서 확인한 취약 지점

alpha.2는 사전 설명 입력에 Foundry의 HTMLProseMirrorElement를 동적으로 생성했습니다. 외부 CSS에서 해당 요소의 높이를 `100%`로 지정했지만 부모는 주로 최소 높이만 가지고 있었으며, 실제 본문의 글자색·배경색을 모듈이 직접 보장하지 않았습니다. 이 구조는 테마와 내부 편집기 레이아웃에 의존합니다.

사전 편집 창은 렌더링 때 입력기를 다시 생성했고, 사전 필드에는 조합 중 저장·재렌더링을 막는 처리가 없었습니다. 채팅용 ProseMirror 플러그인의 수명 주기도 사전·저널 편집기까지 등록하고 있었습니다. 입력기 구성이 한글 조합과 간섭할 여지가 있었으며 기존 테스트는 사전 편집기를 모형으로 대체해 이 경로를 검사하지 못했습니다.

ProseMirror에는 [한국어 조합 글자 유실](https://github.com/ProseMirror/prosemirror/issues/1484), [Windows/Chromium의 CJK 중복·삭제](https://github.com/ProseMirror/prosemirror/issues/1551) 보고도 있습니다. 다만 사용자의 OS·브라우저·Foundry에 포함된 편집기 버전으로 재현한 것은 아니므로 **이번 `가ㄱ` 현상이 특정 상위 버그 때문이라고 확정할 수는 없습니다.** CSS와 통합 구조의 문제는 코드로 확인했고, 정확한 운영체제 수준 원인은 확인 대기입니다.

## 변경

- 사전 입력기에서 Foundry ProseMirror 통합을 제거하고 브라우저 기본 contenteditable 입력을 사용합니다. 저장 데이터는 동일한 HTML 형식입니다.
- 입력·composition 이벤트에서 본문을 재작성하거나 `event.data`를 추가하지 않습니다. 브라우저가 조합 중인 텍스트 노드를 그대로 소유합니다.
- 서식 변경은 사용자가 도구를 누르거나 붙여넣을 때만 수행합니다. 조합 중에는 서식 변경을 차단합니다. 브라우저 기본 편집 명령을 사용해 기본 실행 취소 기록을 유지합니다.
- 본문 높이 300px, 최소 높이 280px와 밝은/어두운 테마의 글자색·배경색·커서색을 지정합니다. 용어명과 별칭 필드에도 같은 대비를 적용합니다.
- 사전 창을 다시 열도록 요청해도 열려 있는 입력기를 재생성하지 않습니다. 조합 중 저장을 차단하고, 조합 Enter와 직접 클릭한 저장을 구분합니다.
- 사전 입력기를 채팅 자동완성에서 제외하고, 채팅 플러그인은 실제 채팅 ProseMirror 뷰에만 연결합니다.
- 굵게·기울임·밑줄·취소선·제목·목록·링크·이미지·색상과 실행 취소·다시 실행을 제공합니다. 이미지 도구는 Foundry 파일 선택기를 사용합니다.
- 초기 HTML, 붙여넣기와 저장 시 안전한 HTML 정제를 유지합니다. 사전 형식 버전과 모듈 ID는 바꾸지 않았습니다.

## 검증 범위

총 45개 자동 테스트 중 9개가 새 입력기와 회귀 경로를 검사합니다. `ㄱ → 가 → compositionend(data="가")`에서 모듈이 본문·커서를 변경하지 않는지, 조합 중 저장과 재렌더링이 차단되는지, 명칭 필드에서도 조합 Enter가 저장하지 않는지, 직접 클릭한 저장이 최종 글자를 한 번만 보관하는지 검사했습니다. 스타일 검사는 CSS 선언을 검사한 것이며 실제 화면 렌더링 검사는 아닙니다.

테스트는 jsdom의 합성 composition 이벤트를 사용했습니다. **Windows 한국어 IME, 실제 Foundry 서버, 브라우저의 native 서식 명령과 파일 선택기 전체 흐름은 아직 실기 검증하지 않았습니다.** 사용자의 두 증상이 같은 환경에서 해소됐다는 확인까지 완료한 것은 아닙니다. 실기 절차는 ALPHA-TEST-CHECKLIST.md에 추가했습니다.
