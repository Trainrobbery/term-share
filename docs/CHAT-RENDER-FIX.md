# 채팅 미출력 조사와 수정

대상: 0.1.0-alpha.4 → 0.1.0-alpha.5 · 2026-11-02

## 확인한 결함

alpha.4의 `renderTermMessage`는 카드에서 메시지 루트까지 올라가며 경로 밖의 모든 형제 노드를 삭제했습니다. 이때 Foundry의 기본 `.message-header`, 시간과 버튼도 사라집니다. 이후 다른 렌더 훅이나 표시 코드가 이 노드를 참조하면 null 참조 오류가 발생할 수 있습니다. 기존 테스트는 헤더가 삭제되었는지만 확인했고 후속 소비자의 참조 가능 여부를 확인하지 않았습니다.

추가한 회귀 검사에서 모듈 훅 다음에 등록한 독립 DOM 소비자가 `.message-header`와 `.message-timestamp`를 참조하도록 구성했습니다. 수정 전에는 `Cannot read properties of null (reading 'dataset')` 오류로 실패했습니다. 이 소비자는 Foundry 내부 구현을 복제한 것이 아닙니다.

방어 처리의 부족도 확인했습니다. HTMLElement 대신 래퍼가 전달되면 `html.matches is not a function`이 발생했고, 잘못된 입력으로 채팅 로그 전체를 전달하면 다른 메시지까지 제거했습니다. 공식 훅의 인자는 HTMLElement이므로 이 두 입력이 실제 사용자 환경에서 전달됐다는 의미는 아닙니다.

실제 사용자 환경의 Foundry 빌드·시스템·콘솔 오류는 확보하지 못했습니다. 따라서 보고된 미출력의 유일한 원인을 확정하지는 않습니다. 이번 수정은 확인한 DOM 파괴 결함과 관련 실패 경로를 제거합니다.

## 수정

- 기본 헤더·시간·버튼, 컨테이너, 링크 및 모든 자식 노드를 삭제하거나 재생성하지 않습니다.
- 주변 요소에 숨김 클래스를 붙이고 모듈 CSS에서만 표시를 끕니다. 카드 제목과 본문은 계속 보입니다.
- 메시지 하나를 나타내는 루트와 그 안의 카드를 확인한 뒤 표시를 바꿉니다. 채팅 로그 전체나 알 수 없는 입력에는 변경을 적용하지 않습니다.
- 레거시 통합의 DOM 래퍼를 처리하며, 알 수 없는 구조에서는 기본 카드 표시를 유지합니다.
- 이전 카드의 공유 안내와 사전 푸터도 노드를 남긴 채 숨깁니다. 저장된 메시지 본문과 사전 데이터 형식은 바꾸지 않습니다.

## 검증

새 회귀 검사 3개는 수정 전 모두 실패하고 수정 후 모두 통과했습니다. 후속 헤더·시간 참조, DOM/리스너 보존, CSS의 주변 요소 숨김과 카드 표시 경로, 중복 적용, 래퍼 입력, 잘못된 루트·인접 메시지 보호를 포함합니다. 전체 자동 테스트는 50개입니다.

검사는 Node/jsdom과 계약 모형에서 실행했습니다. 실제 Foundry V13/V14, 브라우저 화면, 운영체제 IME나 외부 채팅 모듈 조합에서의 해소를 확인한 결과는 아닙니다. 실기에서는 새 카드·이전 카드·일반 채팅, 재접속과 시간 갱신을 함께 확인해야 합니다.
