# Term Share · 용어 사전 공유

**버전: 0.1.0-alpha.12 · 대상: Foundry VTT V13–V14 · 한국어/영어 UI**

GM이 등록한 공개 용어 설명을 플레이어가 `/? 용어` 또는 `/term 용어`로 공유하는 시스템 독립형 모듈입니다. 설치에 별도 라이브러리나 npm 작업이 필요하지 않습니다.

> 이 알파는 공식 V13/V14 API를 기준으로 구현하고 자동 테스트를 통과한 배포 후보입니다. 실제 Foundry 실행, 운영체제의 한글 IME, 두 사용자 간 동기화와 다른 모듈과의 공존은 아직 검증하지 않았습니다. `verified` 버전은 실기 검증 전까지 manifest에 기재하지 않았습니다.

## 설치

1. ZIP을 풀어 `term-share` 폴더를 Foundry 사용자 데이터 폴더의 `Data/modules/` 아래에 넣습니다.
2. 최종 경로가 `Data/modules/term-share/module.json`인지 확인하고 Foundry 서버를 재시작합니다.
3. 월드에 GM으로 접속해 **모듈 관리**에서 **Term Share — 용어 사전 공유**를 활성화하고 새로고침합니다.
4. **게임 설정 → 설정 구성 → Term Share → 사전 관리 열기**에서 용어를 추가합니다.

GitHub 배포 주소는 `Trainrobbery/term-share`에 맞춰 설정했습니다. 저장소를 공개하고 배포 파일을 게시한 뒤에는 Foundry의 **모듈 설치 → Manifest URL**에 다음 주소를 입력할 수 있습니다.

```text
https://raw.githubusercontent.com/Trainrobbery/term-share/main/module.json
```

위 주소로 설치·업데이트하려면 저장소를 공개하고 릴리스 ZIP을 게시해야 합니다. 공개 배포 절차와 정확한 태그·첨부 파일명은 `docs/GITHUB-RELEASE.md`에 있습니다. GitHub에 소스를 비공개로 보관하는 것만으로는 Foundry의 기본 URL 설치를 제공할 수 없습니다. V12 이하와 V15 이상은 대상에서 제외했습니다.

이전 알파를 설치했다면 같은 `term-share` 폴더를 새 패키지로 교체하고 서버를 재시작합니다. 모듈 ID, 설정 키와 사전 JSON 형식 버전(1)은 유지했으므로 기존 사전 데이터를 이어서 사용합니다. 변경 내역은 `docs/CHANGELOG.md`에 있습니다.

## 빠른 체험

사전은 처음에 비어 있습니다. **JSON 가져오기**에서 패키지의 `examples/sample-dictionary.ko.json`을 선택한 다음 미리보기를 확인하고 **가져오기 적용**을 누르면 예시 용어 3개를 사용할 수 있습니다. 예시 설명은 특정 게임 시스템의 실제 규칙이 아닙니다.

채팅창에 `/? 출`을 입력하면 **출혈**이 추천됩니다. **Tab**으로 `/? 출혈`을 완성하고, **Enter**로 공유합니다. `/term Bleeding`도 같은 용어를 공유합니다. 부분 검색어 `/? 출`에서 Enter만 누르면 용어가 일치하지 않는다는 개인 알림을 표시합니다. 현재 선택된 자동완성 항목의 오른쪽에는 `TAP`이 흐리게 표시됩니다. 한글 조합 중에도 입력 글자를 기준으로 목록을 바로 갱신하므로 `/? 중` 뒤에 공백을 추가하지 않아도 추천을 볼 수 있습니다. 조합 중 Tab이나 마우스로 항목을 고르면 글자가 확정된 뒤 완성을 적용합니다. 추천 표시만으로 입력 글자·커서·편집기 상태를 다시 쓰지 않습니다.

| 입력 | 동작 |
|---|---|
| `/? 출혈`, `/term 출혈` | 정확한 용어 또는 별칭으로 조회하고 공개 카드 생성 |
| `/?`, `/term` | 추천 목록 표시; Enter를 누르면 검색어 입력 안내 |
| ↑ / ↓ | 추천 항목 이동 |
| Tab / 마우스로 추천 항목 선택 | 정식 명칭으로 완성; 자동 전송하지 않음 |
| Enter | 현재 입력된 정확한 용어 공유 |
| Esc | 추천 목록 닫기 |
| Shift + Enter | 기존 채팅의 줄바꿈 동작 유지 |

정확한 용어나 별칭을 입력한 뒤 Enter를 한 번 누르면 Tab 선택 없이 공유합니다. 한글을 조합하는 중 Enter를 누르면 조합 확정은 허용하고, 마지막 글자가 입력창과 편집기 상태에 반영된 뒤 공유합니다. 조합 종료 직후의 Enter도 무시하지 않고 처리하며, 이때 발생하는 불필요한 줄바꿈을 차단합니다. Shift+Enter는 줄바꿈으로 유지합니다. 입력을 수정하거나 포커스를 옮기면 대기 중인 전송을 취소합니다. 실제 운영체제별 IME 검증은 남아 있습니다. 수정 근거는 `docs/CHAT-ENTER-FIX.md`에 있습니다.

## 사전 관리

GM만 용어 추가·수정·삭제와 JSON 가져오기·내보내기를 사용할 수 있습니다. 명칭, 별칭, 설명을 입력하고 저장합니다. 별칭은 **한 줄에 하나씩** 입력합니다. 설명 위의 도구로 제목·문단, 굵게·기울임·밑줄·취소선, 목록, 링크, 이미지, 글자색을 넣을 수 있습니다. 이미지 도구는 Foundry 파일 선택기를 우선 사용합니다.

alpha.3에서는 사전 설명 입력기를 브라우저 기본 리치 텍스트 입력으로 교체했습니다. 본문 높이와 밝은/어두운 테마의 글자색·배경색을 명시하며, 한글 조합 중에는 본문 DOM을 재작성하거나 저장하지 않습니다. 조합 Enter와 직접 누른 저장 버튼을 구분합니다. 관련 원인 조사와 검증 한계는 `docs/EDITOR-FIX.md`에 있습니다.

모든 정식 명칭과 별칭은 사전 전체에서 유일해야 합니다. 앞뒤 공백을 제거하고, 연속 공백을 하나로 합치며, 영문 대소문자를 무시합니다. 한글 NFC 정규화도 적용합니다. `출혈 상태`와 `출혈상태`는 서로 다른 표기입니다.

목록의 설명 미리보기는 일반 텍스트입니다. 실제 채팅 카드는 리치 텍스트 서식을 표시합니다. 이미지는 공개적으로 접근 가능한 Foundry 파일 경로를 사용하세요. 로컬 파일의 `C:\...` 경로나 Base64 이미지는 사용할 수 없습니다.

사전은 월드 설정에 저장되고 Foundry의 설정 동기화를 사용합니다. 다른 창에서 사전이 변경된 것을 확인하면 오래된 편집 내용으로 저장하는 것을 차단합니다. 이 검사는 서버의 원자적 잠금이 아니므로 **여러 GM이 정확히 동시에 저장하는 경우에는 마지막 저장이 앞선 저장을 덮어쓸 수 있습니다.** 알파에서는 사전 편집을 한 명의 GM이 담당하세요.

## 공개 카드

채팅 카드는 장서 목록 카드 형태입니다. 미색(`#f4efdf`) 바탕에 먹색(`#312d25`) 제목·본문, 회갈색 공유 안내, 1px 갈색 테두리·구분선을 사용합니다. 제목은 20px, 본문은 14px이며 그림자는 없습니다. 밝은/어두운 Foundry 테마에서 같은 색을 유지하고, 글꼴은 설치된 명조·세리프 글꼴만 사용합니다. 별도 이미지·글꼴 다운로드나 런타임 라이브러리는 추가하지 않습니다. 긴 용어와 링크는 좁은 채팅 폭에 맞춰 줄바꿈하고 본문 이미지는 카드 안에 맞춥니다.

용어 박스 안쪽, 제목 바로 위에 **`플레이어명님이 다음 지식을 공유했습니다.`**를 작은 글씨(11px)로 표시합니다. 이름은 공유 시점의 실제 Foundry 사용자명입니다. 같은 박스 안에서 아래로 정식 용어명과 리치 텍스트 설명이 이어집니다. 기본 채팅 헤더·시간·바깥 테두리·여백과 하단의 ‘용어 사전 · Term Share’ 문구는 표시하지 않습니다. 새 안내문은 메시지 본문에 저장됩니다. alpha.6에서 공유한 기존 카드도 다시 표시할 때 안내문을 박스 안쪽으로 옮깁니다. 저장된 메시지 HTML을 다시 쓰지는 않습니다.

이미 출력된 이전 버전의 카드도 새로고침하거나 다시 표시될 때 같은 모양을 적용합니다. 저장된 메시지 본문을 수정하지 않는 표시 변경입니다. alpha.5에서는 기본 채팅 헤더·시간·버튼을 삭제하지 않고 CSS로만 숨깁니다. 후속 렌더링 코드가 이 요소들을 계속 참조할 수 있도록 메시지 DOM 전체와 링크 리스너를 보존합니다. 메시지 ID와 내용 컨테이너도 유지하며 우클릭 메뉴를 사용할 수 있습니다. 수정 근거와 검증 한계는 `docs/CHAT-RENDER-FIX.md`에 있습니다. GM의 기본 헤더 삭제 아이콘도 표시하지 않으므로 메시지 관리는 우클릭 메뉴를 사용합니다.

주사위/메시지 공개 모드와 관계없이 **모든 사용자에게 공개**합니다. 원본 `/? ...` 명령어는 채팅에 남기지 않습니다. 검색 실패는 입력자에게만 알리고 현재 채팅 입력을 유지합니다.

이미 공유한 카드의 본문 HTML은 사전을 수정하거나 용어를 삭제해도 바뀌지 않습니다. 다만 이미지와 외부 링크는 파일 자체를 복사하지 않고 경로를 참조하므로, 참조 파일이 이동·변경되면 기존 카드의 이미지도 영향을 받습니다.

## JSON 백업과 복원

**내보내기**는 전체 사전을 JSON으로 다운로드합니다. 정식 명칭, 별칭, 설명 HTML, ID, 생성·수정 시간과 형식 버전을 포함합니다. 이미지 파일 자체는 JSON에 포함하지 않습니다.

가져오기 방식은 두 가지입니다.

| 방식 | 동작 |
|---|---|
| 병합 | 같은 정식 명칭은 설명·별칭을 갱신하고 기존 ID를 유지. 나머지는 신규 추가 |
| 전체 교체 | 파일에 있는 용어만 남기며, 기존 사전에만 있던 용어는 삭제 |

가져오기 전 추가·갱신·삭제 목록을 확인할 수 있습니다. 기본으로 **적용 전 현재 사전 다운로드**를 선택합니다. 충돌·잘못된 JSON·지원하지 않는 형식이 있으면 전체 적용을 중단합니다. 입력 파일이 바뀌거나 방식이 바뀌면 미리보기를 다시 계산합니다. 사전이 먼저 수정되었다면 파일을 다시 선택하거나 방식을 변경해 최신 미리보기를 확인하세요.

JSON 최상위 형식은 다음과 같습니다. ID와 생성·수정 기록은 생략할 수 있으며 가져올 때 채워집니다.

```json
{
  "module": "term-share",
  "formatVersion": 1,
  "entries": [
    {
      "name": "출혈",
      "aliases": ["Bleeding", "출혈 상태"],
      "description": "<p><strong>예시</strong> 용어 설명입니다.</p>"
    }
  ]
}
```

알파의 입력 상한은 용어 1,000개, 용어명·별칭 각각 120자, 용어당 별칭 30개, 설명 HTML 100,000자, 전체 JSON 5 MiB입니다. 대규모 사전의 실제 Foundry 성능은 아직 측정하지 않았습니다.

## 설정과 충돌 대응

**월드 설정:** GM이 `/? 명령어 사용`을 끌 수 있습니다. `/term`은 항상 제공합니다.

**개인 설정:** 자동완성 사용 여부와 한 번에 표시할 항목 수(3~12, 기본 6)를 설정합니다. 나머지 항목은 스크롤로 봅니다. 개인 설정은 V13/V14의 사용자 설정 범위를 사용합니다.

V13에서는 공식 `chatMessage` 훅으로 명령어를 처리하며 기존 `MESSAGE_PATTERNS`를 덮어쓰지 않습니다. V14에서는 `ChatLog.CHAT_COMMANDS`를 사용합니다. 공개 카드 생성 옵션도 V13의 `rollMode: "publicroll"`과 V14의 `messageMode: "public"`으로 나눠 처리합니다.

자동완성은 V13의 일반 채팅 입력창과 V14의 ProseMirror 입력을 지원합니다. 채팅용 ProseMirror에는 공식 `createProseMirrorEditor` 훅으로 플러그인을 추가해 상태를 연결하며, 채팅 완성과 입력 초기화는 편집기 트랜잭션으로 처리합니다. 사전 입력기는 채팅 자동완성 대상에서 명시적으로 제외합니다. 사전 설명은 브라우저 기본 입력 내용을 저장할 때 읽고 정제합니다. 코어 메서드나 일반 채팅 내용을 교체하지 않습니다.

다른 등록 명령어가 `/?` 또는 `/term`과 겹치거나 Chat Commander가 활성화되어 있으면 GM에게 경고합니다. 외부 모듈의 모든 이벤트 가로채기를 감지할 수는 없습니다. 충돌하면 `/?`를 끄고 `/term`을 사용하거나, 개인 자동완성을 꺼서 어느 UI가 겹치는지 확인하세요. 두 명령어가 모두 가로채지는 환경은 알파의 지원 보장 범위에 포함하지 않습니다.

## 리치 텍스트 처리

공개 사전이므로 GM 비공개 정보를 저장하는 용도로 사용할 수 없습니다. UI에서만 숨기는 비공개 용어 기능은 제공하지 않습니다.

저장·가져오기·카드 생성 시 HTML 허용 목록을 적용합니다. 스크립트, 이벤트 속성, iframe, 위험한 URL, 비밀 블록, 문서 임베드와 임의 CSS는 제거합니다. 일반 강조·문단·목록·표·안전한 색상·링크·이미지는 유지합니다. 허용 목록 밖의 서식은 저장 시 정리됩니다. UUID 문서 링크는 GM 권한으로 미리 펼치지 않으며 Foundry의 사용자별 링크 권한 처리를 따릅니다.

## 검증 범위

`npm test`의 자동 테스트 63개를 통과했습니다. 검색·정규화·충돌·가져오기·HTML 정제·공개 카드 데이터·권한 차단·Tab/Enter/Esc·IME 이벤트·입력창 교체·관리 UI·V13/V14 명령어 처리와 저장 방식, 실제 ProseMirror 라이브러리의 채팅 상태 변경, 사전 입력기의 조합·스타일 회귀 검사, 박스 안 제목 위의 작은 공유 안내·이름 이스케이프·후속 렌더링의 헤더·시간 참조 보존을 포함합니다.

테스트는 Node와 jsdom, Foundry API 계약 모형, 실제 ProseMirror 라이브러리와 실제 사전 입력기 코드에서 실행했습니다. **실제 Foundry 서버, 운영체제 IME와 브라우저 화면을 실행한 검증은 아닙니다.** 서식 명령은 브라우저 기본 편집 명령을 사용하며 실제 지원 여부는 브라우저에 따릅니다. 수동 검증 절차와 미검증 항목은 `docs/ALPHA-TEST-CHECKLIST.md`, 상세 결과는 `docs/TEST-REPORT.md`에 있습니다.

개발자가 테스트를 재실행하려면 모듈 폴더에서 Node 20 이상으로 다음을 실행합니다. 이 작업은 최종 사용자의 Foundry 설치에는 필요하지 않습니다.

```bash
npm ci
npm test
```
